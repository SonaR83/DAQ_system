# Урок 3. `useRef` — ссылки и изменяемые значения

Страница: `/lesson/3`. Код: `app/routes/lesson-3-use-ref.tsx`.

## Назначение

`useRef` возвращает объект `{ current: значение }`, который:

1. **сохраняется между рендерами**, как состояние: это всегда один и тот же объект;
2. **изменяется напрямую**: `ref.current = x`, без сеттера;
3. **не вызывает рендер** при изменении.

Две основные задачи:

- **доступ к DOM-элементу**: фокус, выделение текста, прокрутка, измерение размеров,
  интеграция с не-React библиотеками (графики, карты);
- **хранение служебных значений**, которые нужны коду, но не отображаются: id
  таймера, `AbortController`, флаг «запрос выполняется», предыдущее значение.

## Сигнатура

```ts
const ref = useRef<T>(initialValue)
// ref.current: T
```

`initialValue` используется только при первом рендере. Для DOM-элементов начальное
значение — `null`, React запишет элемент сам:

```tsx
const commentRef = useRef<HTMLInputElement>(null)
<TextInput ref={commentRef} />
```

## Как это работает

При первом рендере React создаёт объект `{ current: initialValue }` и сохраняет его
в ячейке хука. При следующих рендерах возвращает **тот же самый объект**. React не
следит за полем `current` и ничего не делает при его изменении.

Можно представить `useRef` так:

```ts
function useRef<T>(initialValue: T) {
  const [ref] = useState(() => ({ current: initialValue }))
  return ref // сеттер не нужен: объект меняют напрямую
}
```

### Сравнение с `useState` и обычной переменной

|                                 | `let x` в теле компонента | `useState`              | `useRef`                    |
|---------------------------------|---------------------------|-------------------------|-----------------------------|
| Переживает рендер               | нет, создаётся заново     | да                      | да                          |
| Изменение вызывает рендер       | нет                       | **да**                  | нет                         |
| Как изменить                    | `x = 1`                   | `setX(1)` (асинхронно)  | `ref.current = 1` (сразу)   |
| Новое значение видно            | —                         | в следующем рендере     | сразу же, в любом месте кода |
| Для отображения на экране       | нет                       | **да**                  | нет                         |

Пример 1 урока показывает разницу: «ref + 1» меняет `refClicks.current`, но экран не
обновляется, пока что-то другое (кнопка «state + 1») не вызовет рендер.

## Ссылка на DOM-элемент

```tsx
const commentRef = useRef<HTMLInputElement>(null)

<TextInput id="l3-comment" ref={commentRef} />
<Button onClick={() => commentRef.current?.focus()}>Фокус</Button>
```

Что делает React:

1. при первом рендере `commentRef.current === null`, элемента ещё нет;
2. на этапе коммита, после создания `<input>` в DOM, React записывает его в
   `commentRef.current`;
3. при размонтировании элемента React записывает обратно `null`.

Поэтому к `ref.current` у DOM-элемента обращаются в **обработчиках событий и
эффектах**, а не в теле компонента. Во время рендера элемента может ещё не быть.
Оператор `?.` защищает от `null`.

Начиная с React 19 `ref` можно передавать в собственные функциональные компоненты как
обычный проп, без `forwardRef`. Компонент `TextInput` из Flowbite передаёт его
настоящему `<input>`.

## Служебные значения: опрос с ΔU

В примере 3 опрос запускается и останавливается кнопками, без `useEffect`:

```tsx
const timerRef = useRef<ReturnType<typeof setInterval> | null>(null)
const lastValueRef = useRef<number | null>(null)
const busyRef = useRef(false)

const start = () => {
  if (timerRef.current !== null) return       // уже запущен
  timerRef.current = setInterval(tick, 1000)
  setIsRunning(true)                          // а это для экрана — состояние
}

const stop = () => {
  clearInterval(timerRef.current!)
  timerRef.current = null
  setIsRunning(false)
}
```

Почему `timerRef`, а не `useState`:
- id таймера не выводится на экран → рендер при его изменении не нужен;
- `stop` должен получить id **сразу**, а не в следующем рендере.

Почему не обычная переменная `let timerId`: при следующем рендере она создалась бы
заново со значением `undefined`, и `stop` не смог бы остановить таймер.

### ref решает проблему устаревшего замыкания

`setInterval(tick, 1000)` запоминает функцию `tick` из того рендера, в котором была
нажата кнопка «Старт». Если бы `tick` читала состояние (`voltage`), она всегда видела
бы значение из того рендера. Поэтому `tick` использует только ref и сеттеры:

```tsx
const tick = async () => {
  if (busyRef.current) { skippedRef.current += 1; return } // ref читается «вживую»
  busyRef.current = true
  try {
    const value = await fetchLastVoltage()
    setDelta(lastValueRef.current === null ? null : value - lastValueRef.current)
    lastValueRef.current = value
    setVoltage(value)
  } finally {
    busyRef.current = false
  }
}
```

- `lastValueRef` хранит предыдущее измерение для расчёта ΔU;
- `busyRef` не даёт запустить второй запрос, пока не завершился первый (backend ждёт
  LabVIEW до 1,5 с, а таймер тикает раз в секунду).

### Очистка при уходе со страницы

Таймер, созданный кнопкой, нужно остановить при размонтировании:

```tsx
useEffect(() => {
  return () => {
    if (timerRef.current !== null) clearInterval(timerRef.current)
  }
}, [])
```

## Правило: не читать и не писать ref во время рендера

Код в теле компонента должен быть чистым. Если менять `ref.current` при рендере, то
StrictMode, повторные рендеры и прерываемый рендеринг React приведут к
непредсказуемым значениям. Меняйте ref в **обработчиках событий и эффектах**.

Исключение — ленивая инициализация:

```tsx
const controllerRef = useRef<AbortController | null>(null)
if (controllerRef.current === null) {
  controllerRef.current = new AbortController() // выполнится один раз
}
```

В примере 1 значение `refClicks.current` выводится при рендере намеренно, чтобы
показать, что оно «отстаёт» от реального. В рабочем коде так делать не нужно: если
значение нужно показывать, это состояние.

`RenderCounter` (`app/components/RenderCounter.tsx`) тоже построен на ref: счётчик
увеличивается в `useEffect` без зависимостей, а число записывается прямо в DOM через
ref. Если бы счётчик был состоянием, каждое его обновление вызывало бы новый рендер —
бесконечный цикл.

## Типичные ошибки

| Ошибка | Последствие |
|--------|-------------|
| Значение для экрана хранится в ref | экран не обновляется |
| Обращение к `ref.current` DOM-элемента в теле компонента | при первом рендере `null` |
| id таймера в обычной `let` | после рендера id потерян, таймер не остановить |
| id таймера в `useState` | лишний рендер; в `stop` может оказаться устаревшее значение |
| ref указан в зависимостях эффекта как `ref.current` | изменение `current` не вызывает рендер, поэтому эффект о нём не узнает |
