# Урок 1. `useState` — состояние компонента

Страница: `/lesson/1`. Код: `app/routes/lesson-1-use-state.tsx`.

## Назначение

`useState` добавляет в функциональный компонент **переменную состояния** — значение,
которое:

1. сохраняется между рендерами (обычная `let` при каждом вызове функции создаётся
   заново);
2. при изменении через сеттер заставляет React **перерисовать** компонент с новым
   значением.

Используйте `useState` для любых данных, от которых зависит то, что видно на экране:
измеренное значение, флаг «идёт загрузка», текст ошибки, содержимое поля ввода,
включён ли автоопрос.

## Сигнатура

```ts
const [state, setState] = useState<T>(initialState)
```

| Часть          | Что это |
|----------------|---------|
| `initialState` | начальное значение. Используется **только при первом рендере**, в последующих игнорируется. Может быть функцией (см. «Ленивая инициализация»). |
| `state`        | текущее значение **для этого рендера** |
| `setState`     | функция для изменения значения. Принимает новое значение или функцию `prev => next`. |
| `<T>`          | тип значения в TypeScript. Если начальное значение — `null`, тип нужно указать явно: `useState<number \| null>(null)`. |

Сеттер **стабилен**: React возвращает одну и ту же функцию при каждом рендере.
Поэтому сеттеры можно не указывать в зависимостях `useEffect` и `useCallback`.

## Как это работает

### 1. Первый рендер

```tsx
const [voltage, setVoltage] = useState<number | null>(null)
```

React создаёт для компонента ячейку состояния, кладёт туда `null` и возвращает
`[null, setVoltage]`.

### 2. Вызов сеттера

```tsx
setVoltage(14.2034)
```

Сеттер **не меняет** переменную `voltage` сразу. Он:

1. помещает обновление в **очередь** этой ячейки;
2. планирует повторный рендер компонента.

Поэтому сразу после вызова сеттера переменная хранит старое значение:

```tsx
setVoltage(14.2034)
console.log(voltage) // всё ещё старое значение!
```

### 3. Следующий рендер

React снова вызывает функцию компонента. На строке `useState(...)` он берёт ячейку,
применяет к ней все накопленные обновления по порядку и возвращает результат.
Аргумент `initialState` при этом игнорируется.

### 4. Состояние — это «снимок»

Внутри одного рендера `voltage` — **константа**. Все обработчики событий, созданные в
этом рендере, видят именно это значение, даже если выполняются позже (после `await`,
в таймере). Новое значение появится только в следующем рендере, в новых копиях
обработчиков.

### 5. Пакетная обработка (batching)

Если в одном обработчике вызвано несколько сеттеров, React **не** перерисовывает
компонент после каждого. Он дожидается конца синхронного участка кода и делает один
рендер со всеми изменениями. Начиная с React 18 это работает везде: в обработчиках
событий, после `await`, в `setTimeout`.

В примере 1 урока функция `measure` вызывает пять сеттеров, а рендеров получается
всего два:

```tsx
const measure = async () => {
  setIsLoading(true)              // ┐ рендер №1: кнопка заблокирована,
  setError(null)                  // ┘ показан «Измеряем…»
  try {
    const value = await fetchLastVoltage()   // ← ожидание ответа
    setVoltage(value)                        // ┐
    setHistory((prev) => [...prev, value].slice(-10)) // │ рендер №2
  } catch (e) {                              // │
    setError(errorMessage(e))                // │
  } finally {                                // │
    setIsLoading(false)                      // ┘
  }
}
```

### 6. Пропуск рендера при неизменном значении

Перед рендером React сравнивает новое значение со старым через `Object.is`. Если
они равны, рендер дочерних компонентов пропускается. Для чисел и строк сравнивается
значение, а для объектов и массивов — **ссылка** (тот же объект в памяти или
другой). Отсюда правило неизменяемости, см. ниже.

## Функциональное обновление

Если новое значение вычисляется из старого, передавайте в сеттер **функцию**:

```tsx
setClicks((c) => c + 1)
```

React вызовет её с самым свежим значением из очереди обновлений, а не со «снимком»
текущего рендера. Разница видна в примере 2:

```tsx
// clicks в этом рендере = 0
setClicks(clicks + 1) // поставить 0 + 1 = 1
setClicks(clicks + 1) // поставить 0 + 1 = 1
setClicks(clicks + 1) // поставить 0 + 1 = 1   → итог 1

setClicks((c) => c + 1) // 0 → 1
setClicks((c) => c + 1) // 1 → 2
setClicks((c) => c + 1) // 2 → 3                → итог 3
```

Правило: **если новое значение зависит от предыдущего — используйте функцию**.
Особенно это важно в асинхронном коде и таймерах, где «снимок» мог устареть.

## Неизменяемость (immutability)

Объекты и массивы в состоянии нельзя менять «на месте». Нужно создавать новые:

```tsx
// ✗ Мутация: тот же массив → Object.is(старый, новый) === true → рендера нет
marks.push(now())
setMarks(marks)

// ✓ Новый массив
setMarks((prev) => [...prev, now()])
```

Типичные неизменяемые операции:

| Задача             | Массив                                   | Объект                          |
|--------------------|------------------------------------------|---------------------------------|
| добавить           | `[...arr, x]`                            | `{ ...obj, key: value }`        |
| удалить            | `arr.filter((v) => v !== x)`             | `const { key, ...rest } = obj`  |
| заменить           | `arr.map((v) => (v.id === id ? nv : v))` | `{ ...obj, key: newValue }`     |
| ограничить длину   | `[...arr, x].slice(-10)`                 | —                               |
| отсортировать      | `[...arr].sort(...)` (sort мутирует!)    | —                               |

## Ленивая инициализация

Если начальное значение дорого вычислять, передайте **функцию**:

```tsx
const [samples, setSamples] = useState(() => generateSamples(1_000_000))
```

React вызовет её только при первом рендере. В варианте
`useState(generateSamples(1_000_000))` функция вычислялась бы при каждом рендере, а
результат выбрасывался бы. Пример есть в уроке 2: `useState(() => new Date())` в
компоненте `Clock`.

## Где «живёт» состояние

Состояние привязано к **позиции компонента в дереве**, а не к функции. Два
экземпляра одного компонента имеют независимые состояния (см. два канала в уроке
6). Если компонент убрать со страницы, его состояние уничтожается. При повторном
появлении оно снова инициализируется начальным значением (см. часы в уроке 2).

## Типичные ошибки

| Ошибка | Что происходит | Как правильно |
|--------|----------------|---------------|
| Обычная переменная вместо состояния: `let voltage = 0; voltage = 14.2` | экран не обновляется, при рендере значение сбрасывается | `useState` |
| Чтение состояния сразу после сеттера | видно старое значение | используйте вычисленное значение напрямую: `const v = ...; setVoltage(v); use(v)` |
| `setX(x + 1)` несколько раз подряд или в таймере | обновления теряются | `setX((x) => x + 1)` |
| Мутация массива или объекта | экран не обновляется | создавайте копию |
| Вызов сеттера прямо в теле компонента: `setCount(count + 1)` | бесконечный цикл рендеров (React выдаст ошибку «Too many re-renders») | вызывайте сеттеры в обработчиках событий и эффектах |
| Отдельное состояние для того, что можно вычислить: `const [mean, setMean] = useState(0)` при наличии `history` | данные могут рассинхронизироваться | вычисляйте при рендере: `const mean = sum(history) / history.length` |
