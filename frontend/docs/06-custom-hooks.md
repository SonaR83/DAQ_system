# Урок 6. Собственные хуки: `useInterval` и `useVoltage`

Страница: `/lesson/6`. Код: `app/routes/lesson-6-custom-hooks.tsx`,
`app/hooks/useInterval.ts`, `app/hooks/useVoltage.ts`.

## Назначение

Сравните уроки 2 и 3 с уроком 6. Логика «запросить напряжение, обработать ошибку,
опрашивать по таймеру, хранить историю» занимала десятки строк в каждом компоненте.
Если таких компонентов несколько (каналы, разные страницы), код пришлось бы
копировать.

**Собственный хук** — это функция, которая:

1. называется с `use` (`useVoltage`, `useInterval`);
2. внутри вызывает другие хуки (встроенные или собственные);
3. возвращает то, что нужно компоненту.

После этого компонент занимается только отображением:

```tsx
const { voltage, history, stats, error, isLoading, measure, reset } = useVoltage({
  pollMs: isPolling ? period : null,
  historySize: 10,
})
```

## Главное правило: хук делится логикой, а не состоянием

Каждый вызов хука создаёт **свои** ячейки состояния в том компоненте, где он вызван.
На странице урока два канала используют один `useVoltage`, но у каждого своя история,
ошибка и таймер. Вызов собственного хука эквивалентен тому, что его код вставлен
прямо в компонент.

Если данные нужно сделать **общими** для нескольких компонентов, их поднимают в
общего родителя и передают пропсами (или используют `useContext`; в этот курс он не
входит).

## Почему имя должно начинаться с `use`

- Это сигнал для читателя кода и для инструментов (ESLint, React DevTools,
  компилятор React): «внутри есть хуки, к функции применяются правила хуков».
- Собственный хук подчиняется тем же правилам: вызывается только на верхнем уровне
  компонента или другого хука, без условий.
- Функцию **без** хуков внутри не нужно называть `use…`: это обычная функция
  (`computeStats`, `formatVoltage`).

## `useInterval`

```ts
export function useInterval(callback: () => void, delay: number | null): void {
  const savedCallback = useRef(callback)

  useEffect(() => {
    savedCallback.current = callback
  }, [callback])

  useEffect(() => {
    if (delay === null) return
    const id = setInterval(() => savedCallback.current(), delay)
    return () => clearInterval(id)
  }, [delay])
}
```

### Какую проблему решает

С обычным `setInterval` в `useEffect` приходится выбирать из двух зол:

| Вариант | Проблема |
|---------|----------|
| `useEffect(() => { setInterval(callback, d) ... }, [callback, d])` | если `callback` меняется каждый рендер, таймер пересоздаётся каждый рендер |
| `useEffect(() => { setInterval(callback, d) ... }, [d])` | таймер вызывает `callback` из первого рендера — устаревшее замыкание |

### Как устроено решение

- **`useRef`** (урок 3) хранит **последнюю** версию `callback`. Изменение ref не
  вызывает рендер и сразу видно таймеру.
- **Первый эффект** после каждого рендера с новым `callback` обновляет ref.
- **Второй эффект** (урок 2) зависит только от `delay`. Таймер вызывает не саму
  функцию, а `savedCallback.current()`, то есть всегда свежую версию.
- `delay === null` — удобный способ выключить таймер, не нарушая правило «хуки не
  вызывают по условию».

Результат: таймер пересоздаётся только при смене периода, а вызывает всегда
актуальный код.

## `useVoltage`

Файл `app/hooks/useVoltage.ts` собирает все уроки курса:

| Часть хука                        | Хук          | Урок |
|-----------------------------------|--------------|------|
| `voltage`, `history`, `error`, `isLoading` | `useState` | 1 |
| отмена запроса при размонтировании | `useEffect`  | 2    |
| `controllerRef`: текущий запрос и защита от параллельных | `useRef` | 3 |
| `stats`: min, max, среднее по истории | `useMemo`  | 4    |
| `measure`, `reset`: стабильные функции | `useCallback` | 5 |
| автоопрос                         | `useInterval`| 6    |

Ключевые места:

```ts
const measure = useCallback(async () => {
  if (controllerRef.current) return          // запрос уже идёт — новый не начинаем
  const controller = new AbortController()
  controllerRef.current = controller
  setIsLoading(true)
  try {
    const value = await fetchLastVoltage(controller.signal)
    setVoltage(value)
    setError(null)
    setHistory((prev) => [...prev, value].slice(-historySize)) // неизменяемо
  } catch (e) {
    if (!isAbortError(e)) setError(errorMessage(e))
  } finally {
    controllerRef.current = null
    setIsLoading(false)
  }
}, [historySize])

useInterval(measure, pollMs)
```

- `measure` стабильна (`useCallback`), её можно передавать в `memo`-компоненты и
  использовать в эффектах.
- Защита через `controllerRef` нужна, потому что backend ждёт ответа LabVIEW до
  1,5 с, а период опроса может быть 1 с.
- При размонтировании компонента незавершённый запрос отменяется, и его ответ не
  попадёт в состояние компонента, которого уже нет.

### Интерфейс хука

Хорошо спроектированный хук похож на маленький API:

- **вход** — объект параметров с разумными значениями по умолчанию
  (`{ pollMs = null, historySize = 20 }`). Его легко расширять без поломки
  существующих вызовов;
- **выход** — объект с понятными именами. Компонент берёт только то, что ему
  нужно, через деструктуризацию.

## Как выделять собственный хук

1. Найдите в компоненте группу хуков, которые работают вместе (состояние + эффект +
   ref для одной задачи).
2. Перенесите их в функцию `useЧтоТо` в папке `app/hooks/`.
3. То, что раньше бралось из компонента (период, размер истории), сделайте
   параметрами.
4. Верните из хука то, что нужно для отображения и управления.
5. Замените код в компоненте одним вызовом хука.

Не каждый фрагмент кода нужно выносить в хук. Хорошие кандидаты — логика, которая
повторяется или скрывает сложные детали (таймеры, подписки, запросы, отмену).

## Типичные ошибки

| Ошибка | Последствие |
|--------|-------------|
| Ожидание, что два компонента с одним хуком разделяют данные | у каждого своё состояние |
| Вызов хука внутри условия: `if (enabled) useVoltage()` | нарушение порядка хуков; передавайте параметр (`pollMs: null`) |
| Функция-хук без `use` в имени | инструменты не проверят правила хуков |
| Возвращаемые функции не обёрнуты в `useCallback` | эффекты и `memo`-компоненты потребителя перезапускаются каждый рендер |
