# Урок 4. `useMemo` — кэширование вычислений

Страница: `/lesson/4`. Код: `app/routes/lesson-4-use-memo.tsx`.

## Назначение

При каждом рендере выполняется весь код функции компонента, включая вычисления.
Обычно это быстро. Но если вычисление дорогое (обработка большого массива
измерений), а компонент часто перерисовывается по **другим** причинам (ввод текста,
переключение флага), вычисление повторяется впустую.

`useMemo` **запоминает результат** вычисления и пересчитывает его, только когда
изменились зависимости.

## Сигнатура

```ts
const value = useMemo<T>(calculate: () => T, dependencies: unknown[])
```

| Часть          | Что это |
|----------------|---------|
| `calculate`    | чистая функция без аргументов, возвращает значение любого типа |
| `dependencies` | все значения из тела компонента, которые использует `calculate` |
| `value`        | результат `calculate`: свежий или сохранённый |

## Как это работает

```tsx
const memoStats = useMemo(() => computeStats(samples), [samples])
```

1. **Первый рендер.** React вызывает `calculate`, сохраняет в ячейке хука пару
   «результат + зависимости» `[stats, [samples]]` и возвращает результат.
2. **Следующий рендер.** React сравнивает каждую зависимость с сохранённой через
   `Object.is`:
   - все равны → возвращает сохранённый результат, `calculate` **не вызывается**;
   - хотя бы одна изменилась → вызывает `calculate`, сохраняет новую пару.

Хранится **только последний** результат. Если зависимости вернулись к значению,
которое было два рендера назад, вычисление повторится.

`calculate` выполняется **во время рендера**, синхронно. Поэтому он должен быть
чистым: никаких запросов, сеттеров и изменения внешних переменных.

## Разбор урока

| Состояние      | Влияет на статистику | Что происходит при изменении        |
|----------------|----------------------|-------------------------------------|
| `samples`      | да                   | новый массив → пересчёт             |
| `comment`      | нет                  | рендер, но `useMemo` отдаёт кэш     |
| `isMemoEnabled`| нет                  | выбор, кэш или прямой расчёт         |

С 1 000 000 точек `computeStats` (два прохода + сортировка копии) занимает десятки
миллисекунд. При выключенном `useMemo` расчёт выполняется при каждом нажатии клавиши
в поле «Комментарий», и ввод начинает тормозить. При включённом строка «Рассчитано»
не меняется: время и момент расчёта взяты из кэша.

### Почему повторная загрузка вызывает пересчёт

`setSamples(generateSamples(n))` и `setSamples(values)` каждый раз создают **новый
массив**. Даже если числа те же, ссылка другая, и `Object.is` вернёт `false`. Это
следствие правила неизменяемости из урока 1, и оно работает в нашу пользу: любое
изменение данных гарантированно даёт новую ссылку и пересчёт.

### Хуки нельзя вызывать по условию

```tsx
// ✗ Порядок хуков будет меняться — нарушение правил хуков
const stats = isMemoEnabled ? useMemo(() => computeStats(samples), [samples]) : computeStats(samples)

// ✓ Хук вызывается всегда, по условию выбирается только результат
const memoStats = useMemo(() => computeStats(samples), [samples])
const stats = isMemoEnabled ? memoStats : computeStats(samples)
```

## Две причины использовать `useMemo`

### 1. Дорогое вычисление

Ориентир: если вычисление занимает больше ~1 мс. Проверить можно так:

```ts
console.time("stats")
const stats = computeStats(samples)
console.timeEnd("stats")
```

Примеры в DAQ: статистика и фильтрация больших серий, БПФ, подготовка точек для
графика, поиск выбросов.

### 2. Стабильная ссылка на объект или массив

Объект, созданный при рендере, при каждом рендере новый:

```tsx
const options = { threshold, unit: "В" } // новый объект каждый рендер
useEffect(() => { ... }, [options])      // эффект перезапускается каждый рендер
```

`useMemo` сохраняет ссылку, пока не изменятся зависимости:

```tsx
const options = useMemo(() => ({ threshold, unit: "В" }), [threshold])
```

То же нужно для пропсов компонентов, обёрнутых в `memo` (см. урок 5). Для функций
вместо `useMemo(() => fn, deps)` есть короткая запись `useCallback(fn, deps)`.

## Когда `useMemo` НЕ нужен

- Простые вычисления: `history.length`, `voltage * 1000`, `a + b`, фильтрация
  десятка элементов. Сравнение зависимостей стоит примерно столько же.
- Значение используется только в JSX компонента, который и так редко рендерится.

`useMemo` — оптимизация производительности, а не способ сделать код правильным.
Программа должна работать правильно и без него. React вправе в отдельных случаях
выбросить кэш (например, в режиме разработки при горячей перезагрузке модулей), а
StrictMode в режиме разработки вызывает `calculate` дважды.

> **React Compiler.** В новых проектах можно подключить компилятор React, который
> расставляет мемоизацию автоматически. Понимать, что такое `useMemo` и
> `useCallback`, всё равно нужно: так проще читать существующий код и объяснять
> поведение компилятора.

## Типичные ошибки

| Ошибка | Последствие |
|--------|-------------|
| Не указана зависимость | результат «застревает» на старых данных |
| В зависимостях объект, создаваемый при каждом рендере | пересчёт каждый рендер, кэш бесполезен |
| Побочный эффект в `calculate` (запрос, `setState`) | нарушение чистоты рендера; используйте `useEffect` или обработчик |
| Мутация массива-зависимости: `samples.push(x)` | ссылка не изменилась → устаревший результат |
| `useMemo` вокруг каждого выражения | код сложнее, выигрыша нет |
