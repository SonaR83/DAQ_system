## Запуск

1. **Backend** (FastAPI). Из папки `DAQ_backend/src`:

   ```bash
   pip install -r ../requirements.txt
   uvicorn main:app --reload --port 8000
   ```

   Backend принимает HTTP-запросы и пересылает команды в LabVIEW по UDP
   (`127.0.0.1:61557`). Если LabVIEW не запущен, backend ответит ошибкой
   `503 LabVIEW is not listening…`; если запущен, но не ответил за 1,5 с —
   `504 UDP response timeout`; если прислал нечисловые данные — `502`. Страницы
   уроков покажут текст ошибки. Это
   нормально: обработка ошибок тоже часть примеров. В уроке 4 есть кнопки с
   демо-данными, которые работают без устройства.

2. **Frontend**. Из папки `frontend`:

   ```bash
   npm install
   npm run dev
   ```

   Откройте <http://localhost:5173>. Именно этот адрес разрешён в CORS на backend
   (`DAQ_backend/src/core/cors.py`). Если открыть `http://127.0.0.1:5173`, запросы
   будут заблокированы браузером.

   Адрес backend можно изменить переменной окружения `VITE_API_URL`
   (по умолчанию `http://localhost:8000`).

3. **Откройте консоль браузера** (F12 → Console). Примеры пишут туда, когда
   выполняется рендер, эффект или пересчёт.

Другие команды:

| Команда             | Что делает                                         |
|---------------------|----------------------------------------------------|
| `npm run typecheck` | генерирует типы маршрутов и проверяет TypeScript    |
| `npm run build`     | собирает статическое SPA в `build/client`           |
| `npm start`         | раздаёт собранную версию (`vite preview`, порт 4173)|

Код, не относящийся к хукам (запросы, вёрстка), вынесен в `lib/` и `components/`,
чтобы в файле урока оставалось главное.

### Почему выключен SSR

Шаблон React Router по умолчанию рендерит страницу сначала на сервере (Node.js), а
потом ещё раз в браузере (гидратация). Для изучения хуков это мешает: `console.log`
из компонента печатается и в терминале, и в браузере, а эффекты на сервере не
выполняются вовсе. Поэтому в `react-router.config.ts` установлено `ssr: false`:
приложение собирается как обычное одностраничное (SPA), и весь код компонентов
выполняется только в браузере.

## Что такое хук

**Хук** — это функция из React, имя которой начинается с `use`. Она позволяет
функциональному компоненту «подключиться» к возможностям React: хранить состояние
(`useState`), выполнять побочные эффекты (`useEffect`), хранить ссылки (`useRef`),
кэшировать вычисления (`useMemo`, `useCallback`) и т. д.

### Компонент — это функция, которая вызывается много раз

```tsx
function Voltmeter() {
  const [voltage, setVoltage] = useState(0)
  return <span>{voltage}</span>
}
```

Каждый **рендер** — это новый вызов функции `Voltmeter()`. Обычные локальные
переменные при этом создаются заново и «забываются». Хуки дают компоненту память,
которая переживает повторные вызовы.

### Как React понимает, какой хук какой

Хуки не имеют имён: `useState(0)` не знает, что результат вы назовёте `voltage`.
React хранит для каждого экземпляра компонента **упорядоченный список ячеек** и
сопоставляет их с вызовами хуков **по порядку**:

```
рендер 1:  useState(0) → ячейка №0      рендер 2:  useState(0) → ячейка №0
           useState(false) → ячейка №1             useState(false) → ячейка №1
           useEffect(...) → ячейка №2              useEffect(...) → ячейка №2
```

Если порядок вызовов изменится (например, хук внутри `if`), React возьмёт данные не
из той ячейки. Отсюда **правила хуков**:

1. Вызывайте хуки **только на верхнем уровне** компонента или своего хука: не
   внутри условий, циклов, вложенных функций, после раннего `return`.
2. Вызывайте хуки **только из функциональных компонентов React или из своих хуков**
   (функций, имя которых начинается с `use`), а не из обычных функций.

```tsx
// ✗ Неправильно: при isMemoEnabled === false ячейки сдвинутся
if (isMemoEnabled) {
  stats = useMemo(() => computeStats(samples), [samples])
}

// ✓ Правильно: хук вызывается всегда, условие — после (так сделано в уроке 4)
const memoStats = useMemo(() => computeStats(samples), [samples])
const stats = isMemoEnabled ? memoStats : computeStats(samples)
```

### Рендер и коммит

Обновление экрана в React проходит в два этапа:

1. **Рендер.** React вызывает функцию компонента и получает описание интерфейса
   (JSX). Этот этап должен быть **чистым**: никаких запросов, таймеров и изменений
   DOM, только вычисление результата из пропсов и состояния.
2. **Коммит.** React сравнивает новое описание с предыдущим и вносит в настоящий DOM
   только изменения. После этого выполняются эффекты (`useEffect`).

Рендер запускается, когда:
- компонент появляется на странице впервые (**монтирование**);
- изменилось его состояние (вызван сеттер из `useState`);
- перерисовался родитель (если компонент не обёрнут в `memo`, см. урок 5).

Изменение пропсов само по себе ничего не запускает: пропсы меняются только потому,
что перерисовался родитель.

### StrictMode в режиме разработки

Приложение обёрнуто в `<StrictMode>` (так по умолчанию делает React Router). В
режиме `npm run dev` он **намеренно**:

- вызывает функцию компонента дважды за рендер (второй вызов в консоли показан
  бледнее), чтобы найти нечистый код в рендере;
- при монтировании выполняет эффекты по схеме «эффект → очистка → эффект», чтобы
  убедиться, что функция очистки написана правильно.

В собранной версии (`npm run build`) двойных вызовов нет. Это видно в журнале урока
2. `RenderCounter` учитывает эту особенность и не считает проверку StrictMode
лишним рендером.

## Шпаргалка: какой хук выбрать

| Задача                                                         | Хук                         |
|----------------------------------------------------------------|-----------------------------|
| Значение, изменение которого должно обновлять экран            | `useState`                  |
| Синхронизация с внешним миром: таймер, запрос, подписка        | `useEffect`                 |
| Значение между рендерами, которое не нужно показывать          | `useRef`                    |
| Доступ к DOM-элементу (фокус, прокрутка, размеры)              | `useRef`                    |
| Дорогое вычисление по данным, которые меняются редко           | `useMemo`                   |
| Функция для `memo`-компонента или для зависимостей эффекта     | `useCallback`               |
| Одна и та же логика с состоянием в нескольких компонентах      | свой хук `useЧтоТо`         |
| Значение, которое можно вычислить из пропсов или состояния     | **никакой**: посчитайте при рендере |

Последняя строка важна: если значение выражается через имеющиеся данные (например,
`isEmpty = history.length === 0`), не храните его в отдельном состоянии и не
обновляйте в эффекте. Просто вычислите его в теле компонента.
