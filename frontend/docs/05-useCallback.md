# Урок 5. `useCallback` — стабильные функции

Страница: `/lesson/5`. Код: `app/routes/lesson-5-use-callback.tsx`.

## Проблема

Функция, объявленная в теле компонента, при каждом рендере создаётся **заново**:

```tsx
function Parent() {
  const handleMeasure = () => report(precision) // новый объект на каждом рендере
  return <MeasureButton onMeasure={handleMeasure} />
}
```

С точки зрения JavaScript `handleMeasure` из рендера №1 и из рендера №2 — разные
объекты: `fn1 === fn2` даёт `false`, хотя код одинаковый. Обычно это не важно. Но
есть два случая, когда это мешает:

1. функция передаётся в дочерний компонент, обёрнутый в `memo`;
2. функция указана в зависимостях `useEffect`, `useMemo` или другого `useCallback`.

## `memo` — пропуск рендера дочернего компонента

По умолчанию при рендере родителя перерисовываются **все** его дочерние компоненты.
`memo` меняет это поведение:

```tsx
const MeasureButton = memo(function MeasureButton({ title, onMeasure }) { ... })
```

Перед рендером `MeasureButton` React сравнивает каждый новый проп со старым через
`Object.is`. Если все равны, рендер пропускается и используется прошлый результат.

Строки и числа сравниваются по значению. А функция-проп, созданная заново, **всегда
не равна** старой, поэтому `memo` перестаёт работать. Это видно на красной кнопке
урока.

## Назначение `useCallback`

`useCallback` возвращает **ту же самую функцию**, пока не изменились зависимости.

## Сигнатура

```ts
const cachedFn = useCallback(fn, dependencies)
```

| Часть          | Что это |
|----------------|---------|
| `fn`           | функция, которую нужно сохранить (с любыми аргументами, может быть `async`) |
| `dependencies` | все значения из тела компонента, которые использует `fn` |
| `cachedFn`     | сохранённая функция или новая `fn`, если зависимости изменились |

## Как это работает

`useCallback` — частный случай `useMemo`:

```ts
useCallback(fn, deps)  ≡  useMemo(() => fn, deps)
```

1. **Первый рендер:** React сохраняет `fn` и зависимости, возвращает `fn`.
2. **Следующие рендеры:** функция `fn` **создаётся снова** (это обычный код в теле
   компонента), но если зависимости не изменились, React её **выбрасывает** и
   возвращает сохранённую.

`useCallback` не делает создание функции дешевле. Он только сохраняет **ссылку**.
Сам по себе, без `memo` у получателя или без использования функции в зависимостях,
он ничего не даёт.

## Разбор урока

```tsx
// Общая функция: использует только сеттеры (стабильны) → зависимостей нет
const report = useCallback(async (by: string, digits: number) => { ... }, [])

// 1. Новая функция каждый рендер
const handlePlain = () => report("обычная функция", precision)

// 2. Пересоздаётся только при смене precision
const handleMemo = useCallback(
  () => report("useCallback [report, precision]", precision),
  [report, precision],
)

// 3. ОШИБКА (намеренная): precision используется, но не указан
const handleStale = useCallback(
  () => report("…precision забыт", precision),
  [report],
)
```

| Действие                   | Красная (обычная) | Зелёная (`[precision]`) | Жёлтая (`[]`-ошибка) |
|----------------------------|-------------------|-------------------------|----------------------|
| ввод в «Комментарий»       | рендер            | **нет рендера**         | **нет рендера**      |
| смена точности             | рендер            | рендер                  | **нет рендера**      |
| нажатие «Измерить»         | точность верная   | точность верная         | **всегда 2 знака**   |

Обратите внимание: `handleMemo` зависит от `report`. Если бы `report` была обычной
функцией, она менялась бы при каждом рендере, и `handleMemo` тоже. Мемоизация
работает только тогда, когда стабильна вся цепочка.

## Устаревшее замыкание (stale closure)

Функция в JavaScript «запоминает» переменные области, где она была создана
(**замыкание**). `handleStale` создана в первом рендере, когда `precision === 2`.
Поскольку `precision` нет в зависимостях, `useCallback` никогда не заменит её на новую
версию, и она навсегда видит `precision === 2`.

Это самая частая ошибка с `useCallback`, `useMemo` и `useEffect`. Правило:
**в зависимостях должны быть все значения из тела компонента, которые использует
функция**: пропсы, состояние, другие функции и переменные, объявленные в компоненте.
Указывать не нужно:

- сеттеры `useState` и объекты `useRef` (они стабильны);
- импорты и константы, объявленные вне компонента.

В проектах с ESLint правило `react-hooks/exhaustive-deps` проверяет это
автоматически.

### Как уменьшить число зависимостей

Если значение нужно только для вычисления нового состояния, используйте
функциональное обновление (урок 1):

```tsx
// Зависит от count — пересоздаётся при каждом изменении
const inc = useCallback(() => setCount(count + 1), [count])

// Не зависит ни от чего — создаётся один раз
const inc = useCallback(() => setCount((c) => c + 1), [])
```

## `useCallback` в зависимостях эффекта

Вторая причина использовать `useCallback`: функция, используемая в эффекте.

```tsx
const log = useCallback((text: string) => setEntries(...), [])

useEffect(() => {
  log("старт")
  ...
}, [log]) // log стабилен → эффект не перезапускается при каждом рендере
```

Так сделан `useEventLog` в уроке 2 (`app/components/EventLog.tsx`). Без
`useCallback` функция `log` менялась бы при каждом рендере, все эффекты урока 2
перезапускались бы после каждой записи в журнал, а каждый перезапуск добавлял бы в
журнал новую запись — бесконечный цикл.

## Когда `useCallback` НЕ нужен

- Функция передаётся в обычный DOM-элемент (`<button onClick={...}>`) или в
  компонент без `memo`: сравнивать ссылки некому.
- Функция используется только внутри одного обработчика.

## Типичные ошибки

| Ошибка | Последствие |
|--------|-------------|
| Неполные зависимости | устаревшее замыкание, «застрявшие» значения |
| `useCallback` без `memo` у получателя | лишний код без выигрыша |
| `memo` у дочернего компонента, но функция-проп без `useCallback` | `memo` не срабатывает |
| `useCallback` зависит от обычной (не мемоизированной) функции | пересоздаётся каждый рендер |
